# Beat Hunter — 功能清单（逐项理清用）

> 目的：把「完整产品」拆成可讨论、可排期的功能点。  
> 用法：状态栏一起改；**先对齐要不要 / 做到什么程度**，再写实现规格。  
> 状态：`已有` | `部分` | `未做` | `不做` | `待定`  
> 更新：2026-08-03

图例：

| 标记 | 含义 |
|------|------|
| **已有** | 线上/本地已可用，可再打磨 |
| **部分** | 有骨架，完整产品不够 |
| **未做** | 完整产品需要或候选 |
| **不做** | 明确排除（边界） |
| **待定** | 要你拍板 |

## 建议的「一个个理清」顺序

按依赖，建议我们按这个顺序逐项过（每项只定三件事：**要不要 / 做到哪 / 第几期**）：

```text
1. A 核心找伴奏（A1→A6）   ← 先把主产品说圆
2. C 账号与资产（影响持久化形态）
3. D 工程上线（完整项目门槛）
4. B 地下精选（二期模块）
5. 回看 E 边界有没有要改的
```
