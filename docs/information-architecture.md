# 信息架构（IA）

> 所属产品：Beat Hunter  
> 与 [product-concept.md](./product-concept.md) 同步  

---

## 1. 站点地图

```text
Beat Hunter
│
├── /chat                    找伴奏（主产品，对话 Agent）
│   └── 查询参数（可选）
│       ├── ref=<release_id>     站内发行作为参考
│       └── ref_url=<url>        站外参考链接预填
│
├── /explore                 地下精选（列表）
│   └── /explore/releases/:id  发行详情
│         └── CTA → /chat?ref=:id
│
├── /（可选）                 落地介绍 或 重定向到 /chat
└── （以后）/settings 等      账号与偏好（非 v0.1）
```

---

## 2. 全局导航

| 顺序 | 文案（建议） | 路径 | v0.1 |
|------|--------------|------|------|
| 1 | 找伴奏 | `/chat` | 必有 |
| 2 | 地下精选 | `/explore` | 可占位、可隐藏，文案先定 |

原则：

- 两个入口语义互斥、一眼可辨  
- 不用单独的「发现」同时指代伴奏与发行  
- 当前页导航高亮  

---

## 3. 页面职责

### 3.1 `/chat` 找伴奏

| 区域 | 职责 |
|------|------|
| 顶栏 | 全局导航 |
| 主区 | 消息流（用户 / 助手） |
| 结果 | 伴奏卡片列表（可嵌在助手消息内或侧栏） |
| 底栏 | 输入框、发送、加载态 |
| 可选 | 本会话 shortlist 抽屉 |

**不承载：** 发行打分、策展浏览主列表。

### 3.2 `/explore` 地下精选

| 区域 | 职责 |
|------|------|
| 顶栏 | 全局导航 |
| 主区 | 发行卡片网格/列表 |
| 筛选 | 标签等（二期） |

### 3.3 `/explore/releases/:id` 详情

| 区域 | 职责 |
|------|------|
| 元数据 | 标题、艺人、标签、策展语 |
| 外链 | 去各平台听 |
| 评分 | 展示均分 + 用户评分控件（B 阶段） |
| 主 CTA | **用这首当参考找伴奏** |

---

## 4. 跨页跳转约定

| 从 | 到 | 触发 | 参数 |
|----|-----|------|------|
| 发行详情 | `/chat` | 「用这首当参考找伴奏」 | `ref=<release_id>` |
| 任意外链场景 | `/chat` | 用户粘贴 | 无，或落地后粘贴进对话 |
| `/chat` | 源站 | 打开伴奏卡片 | 外链新开标签页 |

`/chat` 读取 `ref` 后应：

1. 解析站内 `Release` 或等价元数据  
2. 预填助手侧「已载入参考：{title}」或直接进入首轮检索  
3. 用户可再补充自然语言约束  

---

## 5. 数据边界（IA 层）

```text
页面 /chat     →  Session, Message, BeatCandidate, Shortlist
页面 /explore  →  Release, Rating, (User)
跳转 ref       →  Release.id → 参考上下文 → 进入伴奏检索
```

两域在服务端分模块/分表；仅通过 `ref` 与显式 API 交叉，避免隐式混用。

---

## 6. 空状态与降级

| 场景 | 处理 |
|------|------|
| `/explore` 未上线 | 导航隐藏或「即将推出」 |
| `ref` 无效 | `/chat` 提示参考无效，退回普通对话 |
| 伴奏源 API 失败 | 深链降级 + 说明文案 |
| 未登录点打分 | 引导登录（B 阶段）；不影响 `/chat` |

---

## 7. v0.1 最小 IA

必做：

- 全局壳 +「找伴奏」  
- `/chat` 完整主路径  

可选：

- 导航上「地下精选」灰色占位  
- 无 `/explore` 真实数据  

二期再补齐 explore 与 ref 跳转。
