# Beat Hunter — 完整产品成熟度与路线

> 目标定位：**可长期演进的正式产品**，不是个人玩具 Demo。  
> 当前代码状态：**垂直切片已通**（找 beat 闭环），距完整产品仍有系统级缺口。  
> 更新：2026-08-03

---

## 1. 目标 interpration（你要的是什么）

「很完整的项目」在这里至少意味着：

| 维度 | 玩具 Demo | 完整产品（目标） |
|------|-----------|------------------|
| 价值 | 能搜出几条 YouTube | 稳定帮歌手**更快找到能唱的伴奏**，可重复依赖 |
| 质量 | 有时准有时飘 | 有策略、有过滤、有抽检、有迭代 |
| 体验 | 能点能聊 | 视觉专业、状态完备、移动可用、信任感强 |
| 工程 | 本机跑起来 | 部署、监控、密钥、配额、失败可恢复 |
| 数据 | 无记忆 | 会话/收藏/偏好（按阶段）可沉淀 |
| 边界 | 文档里写过 | 产品内外一致，不漂成全能音乐 AI |
| 运营 | 无 | 可解释的内容策略（风格、制作人先验等）可维护 |
| 叙事 | 「我接了个 API」 | 「完整 Agent 产品 + 可演示指标」 |

一句话：

> **Beat Hunter = 面向歌手的伴奏发现产品（Web）**；Agent 与检索是手段，完整产品是交付物。

## 2. 当前水位（诚实）

| 能力域 | 水位 | 说明 |
|--------|------|------|
| 产品定义 / 边界 | ★★★★☆ | 文档扎实，一站两页、主线清晰 |
| 找 beat 主路径 | ★★★☆☆ | 真检索 + Intent/query/打分可用，风格覆盖与精度仍粗 |
| 差异化（vs 裸搜） | ★★☆☆☆ | 有理解/多 query/可视化，缺制作人先验与强精排 |
| UI / 品牌感 | ★★☆☆☆ | 暗色壳能用，离「正式产品观感」差一截 |
| 账号与资产 | ☆☆☆☆☆ | 无登录、无跨会话收藏 |
| 地下精选模块 | ★☆☆☆☆ | 仅文档与导航占位 |
| 工程与上线 | ★☆☆☆☆ | 无私有化部署规范、无监控、会话内存 |
| 质量体系 | ★☆☆☆☆ | 无自动化测试、无固定 eval 集常态化 |
| 合规与信任 | ★★☆☆☆ | 有试听声明，缺完整法务/配额/滥用策略 |

**结论：** 方向对、骨架在；**完整度大约 25～35%**（按正式产品口径）。  
之前的 v0.1/v0.2 是**正确的地基**，不是终点。

## 3. 完整产品应具备的模块（全景）

```text
Beat Hunter（完整形态）
├── 体验层
│   ├── /chat 找伴奏（主）
│   ├── /explore 地下精选（支）
│   ├── 落地页 / 关于 / 合规
│   └── 账号：登录、历史会话、收藏 shortlist
├── 智能层
│   ├── Intent 理解（规则 + LLM，可观测）
│   ├── Query 策略（多角度、伴奏域、风格扩展）
│   ├── 多源召回（YT → 市集/B 站…）
│   ├── 过滤/重排（伴奏向 + 制作人先验 + 精排）
│   └── Refine 与约束累积
├── 数据层
│   ├── 会话持久化
│   ├── 用户与收藏
│   ├── 风格/制作人策展配置
│   └──（二期）发行库 Release + Rating
├── 平台层
│   ├── 部署（生产环境）
│   ├── 密钥与配额管理
│   ├── 日志 / 指标 / 告警
│   └── 速率限制与基础防滥用
└── 质量层
    ├── 固定 eval case 集
    ├── 回归（检索质量 + UI 冒烟）
    └── 版本发布说明
```

## 4. 分阶段路线（建议按「可发布」切，不按「功能冲动」切）

### Phase 0 — 已完成：方向与闭环验证

- 产品边界文档  
- `/chat` + 真 YouTube + Intent/query 可视化  
- **出口标准：** 自己能演示三条路径 ✅（基本达到）

### Phase 1 — 可对外 Beta（**只做 Agent / 找伴奏**）

**目标：** 给陌生人用也不尴尬的 **找伴奏产品**；可公开链接。  
**明确不做本阶段：** `/explore` 地下精选（模块保留、后置认真做，见 Phase 3）。

| 工作包 | 内容 | 优先级 |
|--------|------|--------|
| P1-检索可信 | 风格词典扩展、噪音过滤加强、LLM 精排 reason、固定 20 条 eval | P0 |
| P1-制作人先验 | 风格→制作人配置表 + 软加权 | P0 |
| P1-UI 成品质感 | 设计 token、布局密度、空/错/降级、移动端（/chat） | P0 |
| P1-会话持久化 | DB 替代纯内存 | P0 |
| P1-部署上线 | Vercel/同类 + 环境变量 | P0 |
| P1-基础工程 | 限流、日志（intent/query/延迟） | P1 |
| P1-信任文案 | 关于/合规/Beta 说明（服务 Agent 产品） | P1 |

**出口标准（Beta 收口）：**

- [ ] 公开 URL 可用，密钥不在前端  
- [ ] 20 条 eval 有记录，主路径无「全是 rnb」类硬伤  
- [ ] 移动端可完成一次找 beat  
- [ ] 刷新后会话不丢（持久化）  
- [ ] 作品集可录 3 分钟 **找伴奏** 完整叙事  
- [ ] 地下精选仍可仅占位，不阻塞 Beta  

**用户决策（2026-08-03）：** 先同意 Phase 1；地下发行很重要但现在只关注 Agent。

### Phase 2 — 完整主产品（找 beat 做透）

**目标：** 主线能力对得起「完整项目」四个字。

| 工作包 | 内容 |
|--------|------|
| P2-多源 | BeatStars 等（合规 API/深链），统一 BeatCandidate |
| P2-账号 | 登录（OAuth/邮箱）、历史会话列表 |
| P2-资产 | 跨会话 shortlist 收藏、简单分享链接 |
| P2-体验 | 流式状态、更好加载叙事、偏好轻量记忆 |
| P2-质量 | 自动化回归 + 周更制作人/风格表流程 |
| P2-观测 | 打开率、refine 率、失败率看板 |

**出口标准：**

- [ ] 登录用户可回看历史与收藏  
- [ ] ≥2 个有效发现源（或 1 真源 + 1 市集路径完整）  
- [ ] 检索策略可配置、可解释、可迭代  
- [ ] 有基础数据证明「有人在用 / 在 refine」  

### Phase 3 — 产品宇宙补全（地下精选 + 弱连接）

**目标：** 文档里的一站两页真正落地，而不是永远「即将推出」。

| 工作包 | 内容 |
|--------|------|
| P3-explore | 只读策展列表 + 详情 + 外链 |
| P3-评分 | 登录打分、均分展示、防刷基础 |
| P3-弱连接 | 详情 → `/chat?ref=` 完整打通 |
| P3-运营 | 收录工作流（draft/publish） |

**出口标准：**

- [ ] 精选质量达到「愿意收藏站点」  
- [ ] 至少一条完整：详情 → 当参考 → 出伴奏短名单  

### Phase 4 — 巩固与扩展（完整项目「收官感」）

- 性能与成本（缓存 query、配额策略）  
- 可选：音频参考上传、更重 Agent  
- 法律审阅文案、隐私政策  
- 开源/商业化二选一叙事清晰  

**不在完整项目必选项：** 编曲、混音、灰产下载、荐专当主对话。

## 5. 团队节奏建议（一人也能做完整）

不要平行开 10 条线。推荐迭代节奏：

```text
每个 Sprint（1～2 周）只打 1 个「出口标准」
  Sprint 例：
  S1 检索可信 + eval
  S2 制作人先验 + UI 质感
  S3 持久化 + 部署上线  ← 到这里才有「正式产品」外形
  S4 账号 + 收藏
  S5 explore 只读
  …
```

**完整项目的第一座里程碑不是功能最多，而是：公开可访问 + 主路径可靠 + 体验专业。**  
那是 Phase 1 结束，不是 Phase 0。
