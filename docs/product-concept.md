# Beat Hunter — 产品构思与方向

> 版本：v0.2.1 构思稿  
> 更新：明确 Agent **先找 beat**；荐专为**后期附加**，不进 v0.1  
> 状态：方向已对齐，尚未进入完整研发  
> 站点形态：**一站两页**（找伴奏 Agent + 地下发行精选，可分阶段上线）

---

## 1. 一句话定位

**Beat Hunter** 是面向音乐创作侧用户的 Web 产品，当前以**歌手找伴奏**为第一主线：

- **主产品：** 伴奏（beat）发现 Agent——用自然语言和参考歌曲链接，在多平台中快速收成**可试听的短名单**。  
- **相关模块（独立页面）：** 中文地下优质发行整理与用户打分——偏策展与发现，**不塞进找伴奏对话主流程**。  
- **Agent 分期：** 首期**只实现找 beat**；**推荐专辑仅作后期附加能力**（可选），不与找 beat 抢 v0.1 工期与主结果流。

不做编曲、不做混音、不做「帮你写歌」——**先把找伴奏做透**；地下发行作为同站第二入口，分期建设。

---

## 2. 站点信息架构（已决策）

采用 **同一网站、两个不同页面（两个主入口）**，避免把两套任务塞进同一个 Agent 导致意图打架与叙事稀释。

```text
Beat Hunter 站点
├── /chat（或 /）          「找伴奏」——对话 Agent + 伴奏卡片 shortlist   ← 主产品 / v0.1
├── /explore（或 /underground） 「地下精选」——发行浏览 + 详情 + 打分     ← 二期模块
└── 弱连接（可选，二期+）
      发行详情 →「用这首当参考找伴奏」
      → /chat?ref=<release_id 或 url>
```

| 页面 | 路由（建议） | 主任务 | 交互形态 | 数据域 |
|------|--------------|--------|----------|--------|
| 找伴奏 | `/chat` | 发现可试听伴奏 | 对话 + 结果卡片 | 检索候选 `BeatCandidate`、会话 |
| 地下精选 | `/explore` | 发现/评价地下发行 | 列表 + 详情 + 评分 | 策展 `Release`、评分 |

**导航原则：** 顶栏文案写死两个入口（如「找伴奏」「地下精选」），避免用含糊的「发现」混指两件事。

**为何不是冗余：** 任务、内容对象、成功标准、运营成本均不同；页面分离 + 数据分离后，属于**产品宇宙内的相邻能力**，不是同一功能的重复实现。硬塞进同一对话才会冗余。

## 3. 要解决的问题

### 3.1 主线痛点：找伴奏（歌手）

歌手（含说唱、唱作但不自己编曲的人）在选歌/创作前，经常卡在伴奏上：

| 痛点 | 表现 |
|------|------|
| 说不清需求 | 「有点丧但能喊」「适合女声」——不会翻译成检索词 |
| 有参考、不会迁移 | 有喜欢的歌，却不知道去哪找「同气质」的 instrumental / type beat |
| 平台分散 | YouTube、BeatStars、B 站等来回切，听了很多仍定不下来 |
| 时效性 | 灵感和试唱欲望窗口短，搜索过程一长就放弃 |
| 版权模糊 | 不确定练习 / 翻唱 / 发行分别要注意什么（产品侧先做提示，非法务结论） |

### 3.2 支线痛点：地下发行发现（二期）

| 痛点 | 表现 |
|------|------|
| 信息分散 | 中文地下优质发行散落各平台，缺少「可信任的精选入口」 |
| 缺少共识信号 | 想知道圈内/同类听众觉得怎样，需要轻量打分或想听标记 |
| 与创作的断裂 | 听到好专后，不会自动连到「我要按这个气质找伴奏」 |

### 3.3 非问题（明确不优先）

- 制作人「管理自己的 loop / 工程素材库」作为主推荐逻辑  
- 自动编曲、改结构、出分轨  
- 替代专业 A&R 或完整发行/签约链路  
- 未授权批量下载、破解、绕过平台防护  
- 在 v0.1 把「荐专」做成与找伴奏并列的 Agent 主能力（荐专仅后期附加，见 §8.4 / §18）

## 4. 目标用户

### 4.1 找伴奏页（主）

- **歌手 / 说唱人 / 不编曲的唱作人**  
- 需要：为练习、翻唱方向探索、原创填词 **找到合适的伴奏底床**  
- 不需要（本阶段）：自己做 beat、调混音参数  

画像要点：习惯贴链接表达喜好；能靠试唱几句判断合不合适；更关心「能不能用来唱」，其次才是授权购买路径。

### 4.2 地下精选页（二期，可重叠）

- 关注 **中文地下 / 非主流发行** 的听众与创作者  
- 需要：精选浏览、详情、打分/想听  
- 其中创作者子集可通过弱连接进入找伴奏页  

### 4.3 暂不作为主用户

- 职业 Beat Maker（更偏素材库与授权售卖后台）  
- 需要深度编曲协作的团队（远期另评估）

## 5. 产品原则

### 5.1 全站

1. **一站两页、任务分离**：找伴奏与地下发行不共用同一套主交互。  
2. **弱连接优于强耦合**：集成点优先「当参考找伴奏」，不做大一统聊天。  
3. **主线优先交付**：工程与作品集叙事以 Agent 找伴奏为第一优先级。  
4. **合规可公开**：API-first / 链出官方；可写进简历与公开 Demo。  

### 5.2 找伴奏（Agent）

1. **角色优先**：功能用「帮不帮得上歌手找伴奏」衡量。  
2. **短名单优于海量**：默认 3～5 条，不是 50 条信息流。  
3. **参考曲是一等公民**：链接比复杂表单更符合习惯。  
4. **可解释**：说明为什么推（风格、情绪、与参考的关系）。  
5. **链出官方、可试听**：不做灰产批量下载。  
6. **人机协作**：Agent 搜与收窄，最终听感用户决定。  
7. **边界清晰**：不碰编曲业务。  

### 5.3 地下精选（二期）

1. **策展质量优先于条目数量**。  
2. **评分服务于发现**，防刷与冷启动要在设计里预留。  
3. **发行对象 ≠ 伴奏对象**：数据模型与展示字段分开。

## 6. 解决方案概览

### 6.1 找伴奏：核心体验

用户在 **Web 对话页（`/chat`）** 中：

1. 用自然语言描述想要的伴奏气质；和/或  
2. 粘贴 **参考歌曲链接**（可来自站外，或二期从地下精选带入）；  
3. Agent 解析意图与参考风格 → 规划检索 → 多源工具 → **伴奏卡片短名单**；  
4. 反馈（「再快一点」「鼓轻一点」）→ 多轮收窄；  
5. 试听、会话内 shortlist，需要时去源站看授权。  

### 6.2 地下精选：核心体验（二期）

用户在 **`/explore`**：

1. 浏览策展的中文地下优质发行（单曲 / EP / 专等）；  
2. 进入详情看基础信息与外链试听；  
3. 打分或「想听」等轻反馈；  
4. （可选）一键 **用这首当参考找伴奏** → 跳转 `/chat` 并带上参考上下文。  

### 6.3 价值主张

| 对用户 | 对作品集 / 职业叙事 |
|--------|---------------------|
| 找伴奏少切平台，更快试唱 | 完整 Agent：规划、工具调用、多轮、结构化输出 |
| 地下向有精选与口碑信号 | 主项目边界清晰；二期展示内容/数据与跨页工作流 |
| 听到好专可顺手进入找伴奏 | 弱连接体现产品架构能力，而非 scope 失控 |

## 7. 核心用户流程

### 7.1 描述找伴奏

```text
打开 /chat
  → 「找适合女声的慢热 R&B 伴奏，鼓不要太抢」
  → Agent 结构化需求 → 多源检索 → Top 3～5 卡片
  → 试听 / 收藏 / 追问收窄
```

### 7.2 参考曲风格找伴奏

```text
粘贴参考歌 URL（+ 可选补充）
  → parse_reference → plan_queries → search_*
  → 卡片解释与参考的「像与不像」
  → 多轮 refine
```

### 7.3 地下精选 → 找伴奏（弱连接）

```text
/explore 浏览 → 打开某发行详情
  → 点击「用这首当参考找伴奏」
  → /chat?ref=... （预填参考上下文）
  → 进入 7.2 主流程
```

### 7.4 辅助

- 会话 shortlist、授权提示文案  
- 地下页：筛选（风格/年份/形态等，二期再定）

## 8. 功能范围

### 8.1 找伴奏 — 做（v0.1～v0.2）

| 能力 | 说明 |
|------|------|
| Web 对话 UI | 消息流 + 伴奏结果卡片 |
| 自然语言理解 | 风格、情绪、人声向、节奏快慢等 |
| 参考链接解析 | URL → 风格画像与 query hints |
| 多源发现 | YouTube、BeatStars、Bilibili 等（分阶段） |
| 短名单 + 理由 | 结构化 `BeatCandidate` |
| 多轮 refine | 基于反馈再检索/重排 |
| 会话级收藏 | 当前对话内 shortlist |
| 合规提示 | `license_hint` 与默认文案 |
| 站点壳 | 顶栏可预留「地下精选」入口（即使二期再亮） |

### 8.2 地下精选 — 做（建议 v0.2+，可拆）

| 能力 | 说明 |
|------|------|
| 发行列表 / 详情 | 策展条目 + 外链 |
| 用户打分 | 需登录或轻量身份（实现时再定） |
| 与 /chat 的 ref 跳转 | 弱连接 |
| 基础运营字段 | 标签、简介、来源链接、收录状态 |

可再拆：先上 **只读精选列表（无打分）**，再上打分。

### 8.3 明确不做（当前阶段）

- 编曲、改编、自动写 hook / 旋律  
- 混音、母带作为主功能  
- 以本地旧 beat 复用为主推荐（歌手主路径是**新发现**）  
- 灰产下载 / 绕过平台防护  
- 完整支付与签约交易闭环（市集外链即可）  
- **v0.1 Agent 推荐专辑**（后期附加，见 §8.4）  
- 实盘投资类资讯聚合  

### 8.4 以后可考虑

- **Agent 荐专附加能力**（非主路径）：例如风格参考专辑，或用户明确说「荐专」时的子意图 + 独立发行卡；**禁止**与 beat shortlist 混成同一主结果流  
- 更多伴奏源适配器、参考音频文件上传  
- 跨会话偏好、shortlist 分享、轻量 eval  
- 地下精选的关注厂牌、榜单、防刷策略增强  
- 编曲协作等 **另开产品线评估**

## 9. 内容源策略（找伴奏）

### 9.1 分层

| 层级 | 类型 | 代表 | 作用 |
|------|------|------|------|
| 发现 | 视频/音频平台 | YouTube、Bilibili | type beat / 伴奏向试听入口 |
| 市集 | 可购授权 | BeatStars（可扩 Airbit 等） | 发行意向时的正版路径 |
| 参考 | 成品歌 | 站外链接；二期含站内发行 | **只解析风格，不当伴奏结果** |
| 会话 | 用户行为 | shortlist / 反馈 | 收窄与对比，非长期复用曲库 |

说明：主伴奏对歌手多为「新歌新伴奏」，**本地历史 beat 库不作核心**。

### 9.2 接入节奏

| 阶段 | 策略 |
|------|------|
| v0.1 | 参考解析 + **≥1 真实搜索源**（建议 YouTube Data API）+ 其余深链/mock 占位 |
| v0.2 | BeatStars、Bilibili 等加深（合规与 ToS 范围内，官方能力优先） |
| 以后 | Adapter 扩源；重 schema 统一、去重、理由质量 |

### 9.3 合规

- API-first / 链出官方试听  
- 字段：`source`、`url`、`license_hint`  
- 声明：发现与试听参考，商用以源站为准

## 10. Agent 能力设计（仅 /chat）

### 10.1 工具（逻辑）

| 工具 | 职责 |
|------|------|
| `parse_reference` | 参考 URL → 标题、标签猜测、query hints |
| `plan_queries` | 意图 + 参考画像 → 各平台检索计划 |
| `search_youtube` / `search_beatstars` / `search_bilibili` | 召回 |
| `rank_and_explain` | 去重、排序、理由（可与 LLM 合并） |
| `refine` | 按反馈更新约束并再搜/重排 |
| `update_shortlist` | 会话收藏（可选） |

地下精选的浏览与打分 **不是** Agent tool 主路径；最多在跳转后由 `parse_reference` 消费 ref。  
**荐专：** 不进 v0.1 工具集；远期若做，以附加 tool（如 `recommend_releases`）挂上，默认不开启主路径。

### 10.2 `BeatCandidate`（逻辑字段）

- `id` / `title` / `source` / `url`  
- `thumbnail?` / `reason` / `license_hint`  
- 可选：时长、制作人、猜测 BPM/风格标签  

### 10.3 交互原则

- 信息不足时最多追问 **1** 个关键问题  
- 默认给出可试听结果，而非只给「去搜 xxx」  
- v0.1 外部副作用以读和链出为主

## 13. 成功标准

### 13.1 找伴奏

- 尽量一轮内出 shortlist  
- 参考曲路径下理由含风格相关语义  
- 用户愿意第二轮 refine  
- 演示：纯描述 / 参考链接 / 多轮 refine 三条路径  

### 13.2 地下精选（二期）

- 策展条目达到「愿意收藏站点」的最低质量线  
- 打分有基本可用性（非空壳）  
- 「当参考找伴奏」跳转可演示  

### 13.3 工程向（可后置）

- 打开链接/收藏率、工具失败降级、评分防刷基础策略

## 14. 版本路线

| 版本 | 目标 |
|------|------|
| **v0.1** | 站点壳 + **`/chat`** Agent 最小闭环：参考链接 + 1 真源 + 卡片 shortlist + 多轮 refine；`/explore` 可仅占位或隐藏 |
| **v0.2** | 伴奏多源加深、会话收藏与可观测；**`/explore` 只读精选列表**（可选上线） |
| **v0.3** | 地下打分 + ref 跳转打通；偏好/轻量 eval；公开 Demo |
| 远期 | **Agent 荐专附加**（可选）；编曲等另评估；地下运营与防刷增强 |

## 15. 竞争与差异（简述）

| 类型 | 差异 |
|------|------|
| 通用 ChatGPT | 无稳定多源伴奏工具链与卡片 shortlist |
| 纯 Beat 市集搜索 | 少参考曲跨平台发现与对话收窄 |
| 地下乐评/榜单站 | 我们主线是创作向找伴奏；精选是相邻模块而非唯一卖点 |
| 下载/灰产工具 | 合规发现与官方链出 |
| 做歌/编曲 AI | 专注找伴奏，边界清晰 |

---

## 16. 风险与对策

| 风险 | 对策 |
|------|------|
| 平台 ToS / API | 官方 API 优先；深链降级；不靠违法爬取当卖点 |
| 推荐不准 | 短名单 + 强 refine |
| 版权误解 | 文案区分试听与商用；市集标 marketplace |
| **双业务 scope 膨胀** | 一站两页；排期主线优先；文档写死非目标 |
| 单 Agent 双主路径 | **v0.1 只做找 beat**；荐专后期附加，且不与 beat 混主结果流 |
| 打分冷启动/刷分 | 二期设计；可先只读精选 |
| 同质化 AI 聊天 | 坚持歌手角色、参考曲、工具调用与可演示指标 |

---

## 17. 命名与语气

- **Beat Hunter**：猎获/定位伴奏，不是生成伴奏。  
- 语气：简洁、音乐人友好；结果突出 **听** 与 **为什么**。  
- 地下页语气可略偏「厂牌/发行/现场文化」，仍避免过度黑话。

## 18. 当前结论（决策摘要）

| 决策项 | 结论 |
|--------|------|
| 产品名 | **Beat Hunter** |
| 主服务对象 | 歌手（非编曲主业） |
| 主价值 | 快速发现可试听伴奏短名单 |
| 关键输入 | 自然语言 + 参考歌曲链接 |
| 站点结构 | **一站两页**：`/chat` + `/explore` |
| 地下发行 | **独立页面**；策展 + 打分；弱连接回找伴奏 |
| 是否冗余 | 同页混做会冗余；**分页面不冗余** |
| Agent 范围 | **先做找 beat**；荐专 = 后期附加，非首期 |
| 暂缓 | 编曲、灰产下载、本地复用曲库、v0.1 打分社区、**Agent 荐专** |
| 下一工程阶段 | `spec-v0.1` → 技术选型 → `/chat` 空壳 → 最小 Agent 闭环 |
