# Beat Hunter — 思路整理图

> 目的：把已有构思压成「一张图 + 待决清单」，方便对齐后再写 `spec-v0.1`。  
> 更新：2026-08-03  
> 状态：构思对齐用，不绑定实现栈

---

## 0. 读完应记住的三句话

1. **主价值只有一个：** 帮歌手在短时间内拿到「可试听、可解释、可再收窄」的伴奏短名单。  
2. **地下精选是相邻模块，不是主线：** 同站异页、策展+打分，靠「当参考找伴奏」弱连接。  
3. **Agent 分期：** 先只做找 beat；**荐专仅作后期附加能力**，不进 v0.1，也不与找 beat 抢主路径。

## 1. 产品宇宙（心智模型）

```text
                    Beat Hunter 站点
                           │
          ┌────────────────┴────────────────┐
          │                                 │
     【主线 · v0.1】                    【二期 · 相邻】
        /chat                            /explore
     找伴奏 Agent                      地下发行精选
          │                                 │
   自然语言 + 参考曲链接                 策展列表 + 详情 + 打分
          │                                 │
   多源检索 → 短名单卡片                 Release / Rating
          │                                 │
   试听 / refine / 链出源站        「用这首当参考」→ /chat?ref=
          │                                 │
          └────────── 弱连接（仅跳转） ─────┘
```

**不是：** 万能音乐聊天机器人、编曲工具、灰产下载站、地下乐评主站。  
**是：** 创作侧「先找到能唱的底床」+（可选）同站策展入口。

## 3. 主线价值闭环（找伴奏）

### 3.1 用户真正要完成的事

```text
灵感窗口短
  → 说不清检索词 / 只有参考歌
  → 平台分散、听了仍定不下来
  → 需要：马上能试唱的几条 + 为什么像 + 能继续改
```

### 3.2 产品替用户做的事

| 步骤 | 产品动作 | 成功感 |
|------|----------|--------|
| 表达 | 听懂描述 + 吃参考链接 | 「它懂我要什么」 |
| 发现 | 多源召回（分阶段） | 「不用自己切平台」 |
| 收成 | 3～5 卡片 + 理由 | 「短名单可决策」 |
| 收窄 | 多轮 refine | 「第二轮更贴」 |
| 离开 | 外链试听/授权 | 「去源站继续」 |

### 3.3 三条可演示路径（工程与作品集共用）

1. **纯描述：** 「适合女声的慢热 R&B，鼓别太抢」→ shortlist  
2. **参考链接：** 贴歌 URL → 风格相关理由 + shortlist  
3. **多轮 refine：** 「再快一点 / 鼓轻一点」→ 更新名单  

v0.1 验收应以这三条能跑通为硬标准。

---

## 4. 支线价值闭环（地下精选 · 二期）

```text
中文地下发行分散
  → 策展精选（质量 > 数量）
  → 详情 + 外链听
  → 打分给共识信号
  →（可选）当参考 → 进入主线找伴奏
```

**分期：** 只读精选 → 登录打分 → ref 跳转打通。  
**Agent 荐专：** 不进首期实现。远期可作为**附加功能**（例如风格参考专辑、或用户明确说「荐专」时的子意图），仍不替代 `/explore` 的逛与打分主体验，且不与 beat shortlist 混排。

## 5. v0.1 切口（从「想法」切到「可做」）

### 5.1 必做（最小可演示）

| 项 | 说明 |
|----|------|
| 站点壳 | 顶栏「找伴奏」；「地下精选」可隐藏或即将推出 |
| `/chat` UI | 消息流 + 输入框 + 伴奏结果卡片 |
| 意图理解 | 风格 / 情绪 / 人声向 / 节奏等结构化（可粗糙） |
| 参考解析 | 至少一个平台的 URL → 标题/hints（失败可降级为纯关键词） |
| 真实检索源 | **≥1**（建议 YouTube Data API）；其余可 mock/深链占位 |
| Shortlist | 3～5 条 `BeatCandidate` + `reason` + `url` + `source` |
| 多轮 | 基于用户反馈再检索或重排 |
| 合规文案 | 试听参考；商用以源站为准；`license_hint` 可先静态 |

### 5.2 明确不做（v0.1）

- **Agent 推荐专辑**（后期附加，见 §4 / 决策 #7）  
- `/explore` 真实数据与打分  
- 账号体系（找伴奏可匿名会话）  
- 完整多源齐备（BeatStars / B 站可后置）  
- 跨会话记忆、分享 shortlist、支付  
- 编曲 / 上传音频文件当参考（可远期）  

### 5.3 建议的「完成定义」（DoD）

- [ ] 纯描述路径一轮内出可点开的 shortlist  
- [ ] 参考链接路径：卡片理由里有风格相关语义（哪怕简单）  
- [ ] refine 至少一轮可见变化  
- [ ] 单源 API 失败时有说明，不白屏  
- [ ] README / 演示脚本能按三条路径讲完

## 6. 逻辑架构（仍不绑框架）

```text
[Web /chat]
    │  user message | ref query
    ▼
[Agent Orchestrator]
    ├── parse_reference   （可选）
    ├── plan_queries
    ├── search_*          （v0.1: 至少 youtube）
    ├── rank_and_explain
    └── refine
    │
    ▼
[BeatCandidate[]] → 卡片 UI
    │
    └── 用户点击 → 外链源站
```

**数据（逻辑）：**

- 会话：`Session` / `Message`  
- 结果：`BeatCandidate`（id, title, source, url, reason, license_hint, …）  
- 二期才：`Release` / `Rating`

## 8. 风险再压缩（只保留会影响方向的）

| 风险 | 思路层对策 |
|------|------------|
| 做着做着变成「全能音乐 AI」 | 每加功能问：是否让 shortlist 更快更准？否 → 延后 |
| 双业务抢工期 | 文档与排期写死：explore 不进 v0.1 必做 |
| 推荐不准 | 用短名单 + refine 吸收误差，不追求一次完美 |
| 平台 API/ToS | 官方 API + 失败降级；合规是卖点不是负担 |
| 和 ChatGPT 无差异 | 坚持：固定工具链、伴奏卡片、参考曲、可演示指标 |

## 10. 一页「给自己的电梯稿」

> Beat Hunter 帮**不编曲的歌手**用**自然语言或参考歌链接**，在分散的平台里快速收到 **3～5 条可试听伴奏**，并能多轮收窄；需要时链到源站处理授权。  
> Agent **先只做找 beat**；推荐专辑仅作**后期附加**。同站另有**中文地下发行精选**（二期）负责逛与打分，需要时再弱连接回找伴奏。
